# Setup & Testing Guide - Project SIC

This guide provides step-by-step instructions to set up the environment and test the Secure IoT Ad-Hoc Network (SIC) project.

## 1. Prerequisites (Linux)
Ensure you have the required system libraries installed (for DBus and GLib support).

```bash
sudo apt-get update
sudo apt-get install python3-dev python3-pip python3-venv libdbus-1-dev libglib2.0-dev libgirepository1.0-dev libcairo2-dev
```

## 2. Environment Setup
Create a virtual environment to manage dependencies and install the required Python packages.

```bash
# Create virtual environment
python3 -m venv venv

# Activate virtual environment
source venv/bin/activate

# Install dependencies
pip install simplepyble cryptography dbus-python PyGObject
```

*Note: `simplepyble` is used for scanning/connecting, `dbus-python` for the GATT Server, and `cryptography` for security operations.*

## 3. Configuration
Before running, ensure the certificates are generated and the Sink MAC address is correct (if hardcoded scanning is used, though the current logic scans by Service UUID).

1.  **Generate Certificates (if missing):**
    ```bash
    python3 support/pkiGenerator.py
    ```
    This will create `certs/root_ca.*`, `certs/sink.*`, and `certs/node1.*`.

2.  **Verify Device MACs:**
    If you are running the Sink on a specific hardware (e.g., USB Dongle), ensure no hardcoded MACs in `common/scan.py` conflict with your setup. The system primarily searches for the Service UUID `A07498CA-AD5B-474E-940D-16F1FBE7E8CD`.

## 4. Running the Network

### Scenario A: Single Machine (Simulation with Multiple Adapters)
If you have multiple Bluetooth adapters (e.g., internal + USB dongle), you can run both Sink and Node on the same machine.

**Terminal 1 (Sink):**
```bash
# This script uses the default adapter (usually hci0) or attempts to find one.
# Ensure it picks the one intended for the Sink.
python3 sync/core.py
```

**Terminal 2 (Node):**
```bash
# This script is configured to use adapter_index=0 by default. 
# You may need to edit node_main.py line 35 to adapter_index=1 if hci1 is the Node.
python3 node_main.py
```

### Scenario B: Two Machines (Real Deployment)
**Machine 1 (Sink):**
```bash
python3 sync/core.py
```

**Machine 2 (Node):**
```bash
python3 node_main.py
```

## 5. Testing Procedures (CLI Guide)

Once both scripts are running, follow these steps to verify functionality:

### Step 1: Establish Connection
1.  On the **Node** terminal, press `2` to **Scan**. You should see the Sink (or an intermediate node) appear in the list.
2.  Press `3` to **Connect**. The system will:
    *   Connect via BLE.
    *   Exchange Certificates (Handshake).
    *   Derive Session Keys.
    *   Log `[SEC] 🔐 Chave de Sessão Uplink Negociada`.

### Step 2: Verify Network Liveness (Heartbeats)
1.  On the **Node**, check the status using `1`.
2.  Observe the logs on both terminals. You should see `💓 [HEARTBEAT]` messages being broadcast by the Sink and propagated by the Node.

### Step 3: Secure Messaging (End-to-End)
1.  On the **Node**, send a secure message:
    ```
    > 4 Ola Sink, isto e um teste seguro.
    ```
2.  On the **Sink**, verify the receipt:
    ```
    📨 [INBOX SERVICE] Recebido de node1 (Client XXXX)
       Conteúdo: Ola Sink, isto e um teste seguro.
    ```
    This confirms the Routing, E2E Encryption (DTLS-like), and Service Addressing are working.

### Step 4: Fault Tolerance (Simulate Link Failure)
1.  On the **Sink** (or parent node), block heartbeats to the child:
    ```
    > 2 node1
    ```
    (Assuming `node1` is the NID of the connected child).
2.  On the **Node**, watch the logs. You will see "Heartbeats Lost" count increase.
3.  After 3 missed heartbeats, the Node should declare **UPLINK LOST**, disconnect, and begin scanning for a new parent.

## 6. Troubleshooting
*   **"No adapter found":** Ensure Bluetooth is enabled (`sudo hciconfig hci0 up`) and you have permissions (run as sudo if necessary, though `simplepyble` usually handles user permissions via D-Bus).
*   **"Certificate Verification Failed":** Ensure both Sink and Node are using certificates generated by the *same* `pkiGenerator.py` run (check `certs/` folder).
*   **DBus Errors:** Ensure `dbus-daemon` is running.
